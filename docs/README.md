## 3. 命名规则

| 文档类型 | 文件名格式 | 一级标题（H1） | 必须包含的文档头 | 版本后缀 |
| --- | --- | --- | --- | --- |
| 索引 | `README.md` | `# 文档索引` | 无 | 否 |
| 架构全景 | `架构全景图.md` | `# 架构全景图` | `> 文档编号：AC`、`> 项目：PMail`、`> 状态：`、`> 证据基线：` | 否 |
| 路径图 | `技术演进路径图.md` | `# 技术演进路径图` | `> 文档编号：RM`、`> 项目：PMail`、`> 状态：`、`> 证据基线：` | 否 |
| 需求 | `{四位需求号}/{四位需求号}-{中文名称}-{文档类型}.md` | `# {四位需求号} {中文名称} — {文档类型}` | `> 文档编号：`、`> 项目：`、`> 状态：`、`> 证据基线：` | 否 |
| 流程 | `{两位编号}-{中文名称}-v{N}.md` | `# {两位编号} {中文名称}（v{N}）` | `> 文档编号：`、`> 文档版本：v{N}`、`> 项目：PMail`、`> 状态：`、`> 证据基线：` | **是**，仅流程变化才升版 |
| 功能 | `{两位编号}-{中文名称}.md` | `# {两位编号} {中文名称}` | `> 文档编号：`、`> 项目：PMail`、`> 状态：`、`> 证据基线：` | **否** |

强制约定：

1. **H1 编号必须与文件名编号一致**，H1 名称必须与文件名名称一致（校验脚本会比对）。
2. **功能文档不得带 `-vN`**；**流程文档必须带 `-vN`**。
3. 中文与英文/数字之间加空格，如 `01 项目架构`、`Web 与协议鉴权`。
4. 状态取值只有四种口径：`当前代码快照`（功能文档，描述现状）、`已实现`、`主路径已实现`、`外部依赖` 组合（流程文档）。
5. 证据基线统一写 `>` 证据基线：`` `master` @ `<短提交号>` ``，全仓文档须指向同一提交。
6. 流程文档只在**流程本身变化**时新增版本；错别字、链接、措辞、格式一律在当前版本内修正，历史版本只读。
7. 引用其他文档用**相对路径链接**（如 `./03-接口说明.md`、`../流程/06-IMAP服务-v1.md`），不要写绝对路径或 GitHub 绝对 URL。
8. 文档中引用代码证据统一写 `相对仓库根路径:行号`，形如 `server/models/group.go:11-17`。

- **改代码后同步文档**：路由增删 → [02](./功能/02-功能清单.md) 与 [03](./功能/03-接口说明.md)；表结构变更 → [04](./功能/04-数据模型.md)；流程变化 → 新增流程文档版本；术语新增 → [08](./功能/08-领域术语表.md)。
- **改完必须跑文档校验**（见 § 9），链接与表格问题不允许带病提交。
- **提交拆分**：内容新增、索引/导航、规范/脚本分开提交；只有用户明确要求时才提交或推送。
- **不写真实凭据**：文档中禁止出现真实域名凭据、Token、密码、DKIM 私钥、证书私钥，配置只写字段名。

## 9. 文档质量校验

```bash
  --root . --docs docs --flow-dir 流程 --require-status --require-evidence
```

参数说明：

| 参数 | 作用 |
| --- | --- |
| `--root .` | 仓库根目录（链接解析基准） |
