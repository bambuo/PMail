## 3. 命名规则

| 文档类型 | 文件名格式 | 一级标题 | 文档头 | 版本 |
| --- | --- | --- | --- | --- |
| 索引 | `README.md` | `# 文档索引` | 无 | 否 |
| 架构 | `{两位编号}-{中文名称}.md` | `# {两位编号} {中文名称}` | 文档编号/项目/状态/证据基线 | 否 |
| 功能 | `{两位编号}-{中文名称}.md` | `# {两位编号} {中文名称}` | 同上 | 否 |
| 流程 | `{两位编号}-{中文名称}-v{N}.md` | `# {两位编号} {中文名称}（v{N}）` | 同上 + 文档版本 | **是**，仅流程变化时升版 |
| 需求 | `{四位需求号}/{四位需求号}-{中文名称}-{文档类型}.md` | `# {四位需求号} {中文名称} — {文档类型}` | 文档编号/项目/状态/证据基线 | 否 |
| 归档 | `{原文件名}.md` | 保持原文 | 保持原文 | 否 |

强制约定：

1. **H1 编号与文件名编号一致**，H1 名称与文件名名称一致。
2. **功能文档不得带 `-vN`**；**流程文档必须带 `-vN`**。
3. 中文与英文/数字之间加空格，如 `01 项目架构`、`Web 与协议鉴权`。
4. 状态取 `当前代码快照`（功能）、`已实现` / `主路径已实现` / `外部依赖` 组合（流程）。
5. 证据基线统一写 `> 证据基线：` `master` @ `<短提交号>`；目录重编排后代码引用行号待逐篇复验。
6. 引用其他文档用相对路径链接，不用绝对路径或 GitHub 绝对 URL。
7. 代码证据统一写 `相对仓库根路径:行号`，如 `server/models/group.go:11-17`。

## 8. 维护规则

- **改代码后同步文档**：路由增删 → [02 功能与接口清单](./20-功能/02-功能与接口清单.md)；表结构变更 → [03 数据模型](./20-功能/03-数据模型.md)；流程变化 → 新增流程文档版本；术语新增 → [06 领域术语表](./20-功能/06-领域术语表.md)。
- **改完必须跑文档校验**（见 § 9），链接与表格问题不允许带病提交。
- **提交拆分**：内容新增、索引/导航、规范/脚本分开提交；只有用户明确要求时才提交或推送。
- **不写真实凭据**：文档中禁止出现真实域名凭据、Token、密码、DKIM 私钥、证书私钥。
