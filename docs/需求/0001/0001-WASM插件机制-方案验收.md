## 5. 发现并修复的问题

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 文件名 `plugin_wasm.go` 的 `_wasm` 被 Go 识别为 GOOS 构建约束，文件不参与编译 | 改名为 `plugin_wasm_runtime.go` |
| 2 | 计数落盘与状态变更并发时可能用旧状态覆盖新状态 | 状态存储增加 `Upsert`，在锁内基于最新状态只改计数字段 |
| 3 | 停用时先卸载再落计数，计数丢失 | 调整为先 `flushOne` 再 `unload` |
| 4 | 历史进程执行器把插件返回值赋给局部指针，实际回写不生效 | 旧机制已移除，WASM 侧按字段补丁就地回写 |
| 5 | wazero 目录挂载允许 `../` 逃逸，`os.DirFS` 未做 chroot | 首期不开放文件挂载 |
| 6 | Go `c-shared` 插件直接调用导出函数会 `notInitialized` | 执行器实例化后先调用 `_initialize`，再注册钩子 |
| 7 | 同步插件只返回 `Status` 时，整结构覆盖会清空主题/正文/附件 | 返回值改为字段补丁，只回写出现的字段 |
| 8 | 内置反垃圾需要外部模型 API，首期无网络能力 | 新增 `http` 能力、`http_allow` 精确白名单与 `pmail_http_post` |
| 9 | 微信 token 接口是 GET，只有 POST 无法实现 | 新增 `pmail_http_get`，与 POST 共用白名单、超时与响应上限 |
| 10 | 三个插件重复实现 ABI 内存与 HTTP 逻辑 | 新建 `server/hooks/wasm_plugins` 共享模块与 `pluginabi` 包 |
| 11 | 旧进程插件机制与内置进程插件已移除 | 删除 `hooks/framework`、`plugin_host.go` 与三个进程插件；保留 `contract`、`plugin_registry` 与 WASM 实现 |
