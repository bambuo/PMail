> 文档编号：0002-前端对接文档

> 状态：设计稿，待实施
> 证据基线：`develop` @ `3a0a916`

本次升级不新增、不修改后端接口；本文件用于前端团队对接新的技术栈、组件库、类型契约与构建方式。现有接口的请求字段、响应字段、错误码与鉴权方式保持原样。

## 1. 接口与权限

| 项 | 口径 |
| --- | --- |
| 鉴权方式 | 浏览器端继续使用 Cookie 会话；不设置 Token 请求头 |
| 语言请求头 | `Lang: en` 或 `Lang: zhCn` |
| 未登录 | 响应 `errorNo = 403`，前端跳转 `/login` |
| 未初始化 | 响应 `errorNo = 402`，前端跳转 `/setup` |
| 无权限 | 响应 `errorNo = 405`，页面展示后端 `errorMsg` |
| 接口变更 | 无 |

## 2. 字段说明

### 2.1 统一响应包裹

所有接口继续返回以下结构：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `errorNo` | `number` | `0` 表示成功；`402` 未初始化；`403` 未登录；`405` 无权限 |
| `errorMsg` | `string` | 错误文案；成功时为空串 |
| `data` | `object` / `array` / `null` | 业务数据 |

TypeScript 契约：

```ts
export interface ApiResponse<T = unknown> {
  errorNo: number
  errorMsg: string
  data: T
}
```

### 2.2 用户信息

`POST /api/user/info` 的 `data` 字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `account` | `string` | 当前账号 |
| `name` | `string` | 显示名称 |
| `is_admin` | `boolean` | 是否管理员 |
| `domains` | `string[]` | 可用域名列表，主域名在首位 |

TypeScript 契约：

```ts
export interface UserInfo {
  account: string
  name: string
  is_admin: boolean
  domains: string[]
}
```

除上述两个通用结构外，邮件、分组、规则、用户、插件等页面模型按现有接口实际返回字段定义 TypeScript interface，不改变 JSON 字段名与类型。

## 3. 接口明细与示例

本次没有新增或变更接口，不重复列出现有接口契约。前端调用方式保持：

```ts
const res = await http.post<{ /* data 类型 */ }>('/api/...', payload)
if (res.errorNo === 0) {
  // 使用 res.data
}
```

### 3.1 统一响应示例

```json
{
  "errorNo": 0,
  "errorMsg": "",
  "data": {}
}
```

### 3.2 用户信息响应示例

```json
{
  "errorNo": 0,
  "errorMsg": "",
  "data": {
    "account": "user@example.com",
    "name": "User",
    "is_admin": false,
    "domains": ["example.com"]
  }
}
```

### 3.3 前端调用约定

- `http.get<T>()` / `http.post<T>()` 返回 `Promise<ApiResponse<T>>`。
- 响应拦截器在 `errorNo = 403` / `402` 时跳转，页面只处理 `errorNo = 0` 与业务错误。
- 请求体继续使用 JSON；`POST` 请求由拦截器统一序列化。

## 4. 错误文案

| 场景 | 前端展示 |
| --- | --- |
| 业务失败且后端返回 `errorMsg` | `Message.error(res.errorMsg)` |
| 业务失败且 `errorMsg` 为空 | 使用当前页面 i18n 的兜底文案 |
| 成功操作 | `Message.success(...)` 或 `Notification.success(...)` |
| 需要确认的危险操作 | `Modal.confirm({ title, content, onOk, onCancel })` |
| HTTP 错误 | 保持现有拦截器行为：跳转或 `Promise.reject`，由页面兜底 |

错误码与 `errorMsg` 由后端返回，前端不新增错误码，不改写文案映射。

## 5. 注意事项

### 5.1 组件库

- 全部 UI 组件使用 `@arco-design/web-vue`，不再引入 `element-plus` 与 `@element-plus/icons-vue`。
- 组件在模板中直接使用 `a-*`，图标使用 `icon-*`；由 `unplugin-vue-components` 的 `ArcoResolver` 按需引入。
- 函数式服务显式导入：

```ts
import { Message, Modal, Notification } from '@arco-design/web-vue'
```

- 常用 API 差异：
  - `a-table` 使用 `columns` 配置 + `#slotName`，不再使用 `a-table-column` 子组件。
  - `a-form-item` 使用 `field`，不是 `prop`。
  - `a-modal` 使用 `v-model:visible`，不是 `v-model`。
  - `a-textarea` 是独立组件，不是 `a-input type="textarea"`。
  - 危险按钮使用 `status="danger"`，不是 `type="danger"`。

### 5.2 TypeScript

- 所有 SFC 使用 `<script setup lang="ts">`。
- 组件 props / emits 使用泛型声明；接口响应使用 `ApiResponse<T>`。
- 不使用显式 `any`；未知结构用 `unknown` 并在使用点收窄。
- 合并前必须通过 `bun run typecheck`。

### 5.3 构建与包管理

```bash
cd web/desktop
bun install --frozen-lockfile
bun run dev
bun run typecheck
bun run lint
bun run build
```

- 包管理器统一为 bun，锁文件为 `web/desktop/bun.lock`。
- Node 版本为 24 LTS。
- CI 与 Docker 均使用 `bun install --frozen-lockfile`，不再使用 yarn。
- 前端产物仍输出到 `web/desktop/dist`，由 `make build_fe` 复制到 `server/internal/api/dist` 后嵌入 Go 二进制。

### 5.4 暗色模式

- Arco 暗色主题通过 `document.body` 的 `arco-theme="dark"` 控制。
- 页面不再依赖 `prefers-color-scheme` 的 Element Plus 样式覆盖。
- 新增页面不得直接写死浅色/深色；使用 Arco 主题变量。

### 5.5 富文本

- 优先使用 `@wangeditor-next/editor` 6.5.1 与 `@wangeditor-next/editor-for-vue` 6.5.1。
- 若阶段一 POC 不通过，保留 `@wangeditor/*` 5.1.x；对接方不得同时引入两套编辑器。

### 5.6 浏览器与路由

- 使用 History 路由；服务端对非 API 路径回退 `index.html`，刷新 `/detail/1`、`/setup` 等地址可直接打开。
- 保持 Cookie 鉴权与 `Lang` 请求头。
- 不使用需要 IE 兼容的 API；目标浏览器为 Chrome、Safari、Edge 最新稳定版。
