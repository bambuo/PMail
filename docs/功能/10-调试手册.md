## 1. 目的与范围

本手册汇总 PMail 的日常调试手段：协议手工试连（SMTP / IMAP / POP3）、常见故障的定位顺序、测试与构建命令、日志级别的开启方式，以及仓库既有调试素材（邮件原文样本、截图）的归档说明。

本文由原 `docs/debug.md` 整理而来，并补充了源码中可验证的端口、命令与环境变量。**内容只描述现有代码行为，本手册不涉及任何代码改动。**

调试前的三条纪律：

1. 协议调试请用**测试账号**，账号密码会以明文出现在终端历史和 shell 记录里。
2. 远程连 993 / 995 / 465 前先确认本机到目标端口可达（云厂商安全组、防火墙 `25/80/110/443/465/587/993/995`）。
3. 生产环境不要长期把 `logLevel` 开成 `debug`，日志量会显著增大。

## 3. IMAP 手工试连

IMAP 是最常用来判断"服务端到底有没有把邮件存进去"的协议。

### 3.1 建立 TLS 连接

```bash
# 远程服务器（域名换成自己的 imap 域名）
openssl s_client -crlf -connect imap.xxxx.com:993

# 本机调试（需要先在本机运行起服务并监听 993）
openssl s_client -crlf -connect 127.0.0.1:993
```

约定：下文命令中的 `A1`、`A3`、`A4`、`A5` 是 IMAP 命令标签，一个连接内的标签必须唯一；`114`、`115` 是原 `docs/debug.md` 里的写法，同样只是标签，换成任意唯一字符串都能执行。

### 3.2 删除邮件

删除内置邮箱「Deleted Messages」里的全部邮件：

```text
A1 LOGIN testCase testCase
A3 SELECT "Deleted Messages"
A4 UID STORE 1:* +FLAGS.SILENT (\Deleted)
A5 EXPUNGE
```

步骤含义：`SELECT` 选中目标邮箱 → `STORE +FLAGS(\Deleted)` 打删除标记 → `EXPUNGE` 物理删除已标记邮件。

> 如果要清空的是收件箱，把 `"Deleted Messages"` 换成 `"INBOX"`。内置邮箱名称清单见「08 领域术语表」与「06 IMAP服务（v1）」。

### 3.3 搜索邮件

```text
A1 LOGIN testCase testCase
114 SELECT "INBOX"
115 UID SEARCH 1:5 NOT DELETED
```

以上命令返回的是匹配邮件的 UID 列表，可再用 `UID FETCH <uid> BODY[]` 或 `UID FETCH <uid> FLAGS` 查看内容与标记。

### 3.4 常见排错提示

| 现象 | 优先排查 |
| --- | --- |
| 连接建立后无 `* OK` 问候 | 服务进程是否启动、993 是否被防火墙拦截 |
| 登录返回失败 | 账号必须带域名后缀或按登录逻辑补齐；密码是 Web 端登录密码，不是单独设置的应用密码 |
| `SELECT` 报不存在 | 内置邮箱名与预期不符（如 `Sent Messages` / `Deleted Messages` / `Junk`） |
| 客户端看不到新邮件 | 客户端是否走 IDLE 长连接；服务端仅声明 `IMAP4rev1` + `IDLE` 能力 |

## 4. SMTP / POP3 手工试连

```bash
# SMTP STARTTLS 端口
openssl s_client -crlf -connect 127.0.0.1:587 -starttls smtp

# SMTP 隐式 TLS 端口
openssl s_client -quiet -connect 127.0.0.1:465

# POP3 隐式 TLS 端口
openssl s_client -crlf -connect 127.0.0.1:995
```

连通后直接用明文协议命令交互：SMTP 的 `EHLO`、`AUTH`、`MAIL FROM`、`RCPT TO`、`DATA`；POP3 的 `CAPA`、`USER`、`PASS`、`STAT`、`LIST`、`UIDL`、`RETR`、`DELE`。各协议的完整命令集与语义见「07 POP3服务（v1）」与「06 IMAP服务（v1）」。

**发信链路排错顺序**（代码证据 `server/pkg/send/send.go:226`）：先查 MX 记录 → 尝试 `STARTTLS:25` → 回退 `587` → 回退 `465` → 最后 `明文:25`。若发件在某个阶段失败，先确认目标域的 DNS 与对应端口可达性。

### 5.1 权限不足导致测试全失败

测试会真实监听固定端口；在 Linux / macOS 上，**监听小于 1024 的端口需要 root 权限**，普通用户直接 `make test` 会成片失败。此时用：

```bash
sudo env "PATH=$PATH" make test
```

> `env "PATH=$PATH"` 的作用是把当前用户的 `PATH`（含 go、node、yarn）带进 root 环境，避免 `sudo` 下找不到命令。

### 5.2 只跑单个测试

```bash
cd server
go test -v -run ^Test ./internal/app
```

`make test` 会注入两个环境变量，手工单测时建议一并设置，行为才与流水线一致：

| 变量 | 用途 | 证据 |
| --- | --- | --- |
| `setup_port` | 测试期引导服务端口（Makefile 中为 17888） | `Makefile:48`、`server/internal/api/http_setup.go` |
| `PMail_ROOT` | 程序根目录，决定 `config/`、`db` 等相对路径 | `Makefile:48`、`server/config/config.go:57-59` |

```bash
export setup_port=17888
export PMail_ROOT=$(pwd)/
go test -v -p 1 ./...
```

## 6. 日志与运行态观测

| 手段 | 做法 | 证据 |
| --- | --- | --- |
| 日志级别 | 配置文件 `logLevel` 取 `debug` / `info` / `warn` / `error`，缺省与非法值均回落到 `info` | `server/config/config.go:173-183` |
| 日志格式 | JSON 输出到 stdout，并带调用方信息（`SetReportCaller`） | `server/config/config.go:163-168` |
| SQL 打印 | `logLevel=debug` 时自动开启 ORM 的 SQL 显示 | `server/internal/infra/database.go` |

因此：**抓 IMAP 交互细节只需要把 `logLevel` 改成 `debug` 重启进程**，比手工 `openssl s_client` 更完整。

## 9. 已知缺口

- 仓库中**没有**内置 pprof 或其他性能剖析入口（全仓检索无 `pprof`），CPU / 内存问题目前只能靠日志与外部工具（`top`、`pprof` 无关的进程级观测）。
- `logLevel` 只有 `debug` 一个"详细"档，没有更细的按模块开关；排查 IMAP 协议时也会同时打开 SQL 日志。
- 手册中的命令基于 `master` @ `7e868f5` 的源码行为，协议能力集若变更需同步本文。

## 目录分层检查与隔离测试

`make check_arch` 检查 `api/app/domain/infra/bootstrap` 的直接导入及领域层的框架隔离。该检查只验证结构，不能替代协议和事务测试。

完整测试会改写运行配置、创建测试账号并监听协议端口，应在临时副本中设置 `PMail_ROOT` 后执行，避免使用个人邮箱数据。目录迁移前的隔离基线有四个叶子用例失败：`TestMaster/testUser2EmailList`、`TestMaster/testUser2DelEmail`、`TestSelect`、`TestCopy`；比较迁移结果时应保留原断言。
