本文件逐条列出 PMail 后端对外暴露的 HTTP 接口：路由注册、鉴权方式、请求体、响应 `data` 结构与错误码。所有结论均来自 `server/` 源码；每条结论后给出「相对仓库根目录的路径:行号」，便于复核。组件职责与启动顺序见 [01 项目架构](./01-项目架构.md)，数据表字段与枚举见 [04 数据模型](./04-数据模型.md)。

## 1. 阅读前提

| 项 | 事实 | 证据 |
| --- | --- | --- |
| 路由机制 | 标准库 `http.ServeMux`，**只按路径前缀分发，不区分 HTTP method**；同一路径 GET/POST 行为完全一致 | `server/internal/api/http_routes.go`、`:33`-`:58` |
| 请求体 | 绝大多数接口**无论 method 如何都读取请求体 JSON**（`io.ReadAll(req.Body)` 后 `json.Unmarshal`） | `server/internal/api/email_list_handler.go`、`server/internal/api/auth_handler.go` |
| 前端调用 | 前端统一用 `http.post`/`http.get` 混合调用，实测并无 method 约束 | `web/desktop/src/components/HomeAside.vue:61`、`web/desktop/src/views/ListView.vue:131` |
| 响应外壳 | 统一为 `{"errorNo":int,"errorMsg":string,"data":any}`；`Content-Type` 在 `contextIterceptor` 中默认设为 `application/json` | `server/dto/response/response.go:16`、`server/internal/api/http_middleware.go` |
| 语言 | 文案语言取请求头 `Lang`，空值回退 `en`；仅 `zhCn` 返回中文 | `server/internal/api/http_middleware.go`、`server/internal/app/translation.go` |

### 1.1 错误码

错误码是业务码，与 HTTP 状态码无关（成功与失败都返回 HTTP 200）。

| 常量 | 值 | 含义 | 证据 |
| --- | --- | --- | --- |
| （成功） | `0` | `NewSuccessResponse` 不设置 `ErrorNo`，零值即 0 | `server/dto/response/response.go:27` |
| `ParamsError` | 100 | 参数错误 / 校验失败 | `server/dto/response/response.go:12` |
| `NeedSetup` | 402 | 系统未完成初始化，先走引导 | `server/dto/response/response.go:9` |
| `NeedLogin` | 403 | 未登录 / session 过期 / Token 无效或过期 | `server/dto/response/response.go:10` |
| `NoAccessPrivileges` | 405 | 已登录但无权限（仅管理员接口） | `server/dto/response/response.go:11` |
| `ServerError` | 500 | 服务端异常（含 DB 错误、发件失败） | `server/dto/response/response.go:13` |

`errorMsg` 字段：成功响应为空串；失败时可能是固定英文串（如 `"params error"`）、i18n 文案（如 `"登录已失效"`），也可能是原始 `error.Error()` 文本。`data` 字段：失败时通常为 `""`（空串），个别接口把错误详情放进 `data`。

### 1.2 鉴权模型（`contextIterceptor`）

所有经 `contextIterceptor` 包装的路由（见第 2 节标注）执行同一套鉴权，顺序如下（`server/internal/api/http_middleware.go`）：

```mermaid
flowchart TD
  A[进入 contextIterceptor] --> B{config.IsInit?}
  B -- 否 --> B1{路径 == /api/setup ?}
  B1 -- 否 --> B2["返回 402 NeedSetup"] --> Z[结束]
  B1 -- 是 --> H[交给处理函数]
  B -- 是 --> C{"session 中 user 的 ID > 0 ?"}
  C -- 是 --> H
  C -- 否 --> D{"请求头 Token 非空 ?"}
  D -- 是 --> E{"校验 Token 通过 ?"}
  E -- 否 --> E1["返回 403 NeedLogin"] --> Z
  E -- 是 --> H
  D -- 否 --> F{"路径是 /api/ping 或 /api/login ?"}
  F -- 是 --> H
  F -- 否 --> F1["返回 403 NeedLogin"] --> Z
```

三种鉴权状态：

| 标记 | 含义 | 判定依据 |
| --- | --- | --- |
| **无需登录** | 不包装 `contextIterceptor`，或虽包装但被豁免 | 未包装：`/.well-known/`（`server/internal/api/http_routes.go`）、`/api/ping`（`:33`）；豁免：`/api/login`（`server/internal/api/http_middleware.go`） |
| **session** | 有效 scs session（Cookie）即通过 | session 中 `user` JSON 的 `ID > 0`，取自 `models.User`（`server/internal/api/http_middleware.go`、`server/internal/api/auth_handler.go`） |
| **session 或 Token** | session 无效时允许用请求头 `Token` 登录 | 请求头 `Token` 非空且校验通过（`server/internal/api/http_middleware.go`）；Token 算法见第 1.2 节正文（`https_server.go:144`-`:169`） |

Token 格式（**只写结构，不写任何真实值**）：`{account}:{MD5(user.Password + timestamp)}:{timestamp}`。字段 `account` 为账号，第二个字段是 `password.Md5Encode(fmt.Sprintf("%s%d", user.Password, requestTimeStamp))`，第三个字段是 Unix 秒级时间戳；服务器时间与时间戳相差 `>= 5` 秒即视为过期（`server/internal/api/http_middleware.go`）。即 Token 有效期极短、需要每次请求重新计算，属于“按请求签名的临时凭证”。

### 1.3 管理员判定与权限矩阵

`ctx.IsAdmin` 来自当前用户的 `models.User.IsAdmin == 1`（`server/internal/api/http_middleware.go`）。只有以下 4 个接口在函数内部做了**角色校验**，其余接口仅要求登录：

| 接口 | 角色要求 | 证据 |
| --- | --- | --- |
| `POST /api/user/create` | 管理员 | `server/internal/api/account_handler.go` |
| `POST /api/user/edit` | 管理员 | `server/internal/api/account_handler.go` |

## 2. 正常运行态路由清单

统计口径（可复算）：

- `router()` 函数内 `mux.HandleFunc(...)` 调用共 **34** 条（`server/internal/api/http_routes.go`）。
- 另有非 `HandleFunc` 的 `mux.Handle("/", http.FileServer(...))` 静态资源兜底 **1** 条（`server/internal/api/http_routes.go`），不计入接口数。
- 即：**接口总数 = 34**，按前缀分类不重不漏如下。

| 分类 | 数量 | 编号区间 | 明细 |
| --- | --- | --- | --- |
| `/api/` 接口 | 30 | #1-#30 | ping 1（#1）+ login/logout 2（#2-#3）+ group 4（#4-#7）+ email 6（#8-#13）+ settings 1（#14）+ rule 4（#15-#18）+ user 4（#19-#22）+ plugin 8（#23-#30） |
| 非 `/api/` 接口 | 3 | #31-#33 | `/attachments/`、`/attachments/download/`、`/.well-known/` |
| 合计 | **34** | #1-#34 | 见 2.1、2.2 两节 |

> 口径自查：`/api/` 30 条 + 非 `/api/` 3 条 = **33** 条可调用 `HandleFunc` + 静态资源兜底 1 条 = **34**。`grep -c "mux.HandleFunc" server/internal/api/http_routes.go` 为 36，减去重定向模式下的 2 条，即 34；`mux.Handle("/", ...)` 静态资源在第 2.2 节以 #34 列出仅供对照。

运行时挂载点说明：`router()` 被 HTTPS 服务（`server/internal/api/http_middleware.go`）调用，并在 `httpsEnabled == 2`（关闭 HTTPS）时被 HTTP 服务调用（`server/internal/api/http_routes.go`）。HTTPS 服务的外部入口还套了一层 `session.Instance.LoadAndSave(mux)`（`server/internal/api/http_middleware.go`）。

| 箱 | `tag` | 证据 |

`/api/email/send` 的 `attrs`（附件）每项为 `{name, data}`，`data` 必须是 `data:{contentType};base64,{base64}` 形式的字符串，服务端按 `;` 切分后取 `infos[0]` 作 `Content-Type`、取 `infos[1]` 去掉 `base64,` 前缀后 Base64 解码（`server/internal/api/email_send_handler.go`、`:146`-`:161`）。解码失败返回 100 + i18n `att_err`。

`/api/email/send` 的服务端默认值（缺省即生效）：`from.email` 为空时取 `{当前账号}@{config.Domain}`；`from.name` 为空时取当前用户名；`sender` 为空时回落为 `from`（`server/internal/api/email_send_handler.go`）。

### 2.4 WASM 插件管理接口

共同约定：

- 6 条接口全部要求管理员身份（`ctx.IsAdmin`），非管理员返回 `errorNo=405`。
- 由于 `http.ServeMux` 不区分 method，handler 内显式校验：list 仅接受 `GET`，其余仅接受 `POST`；不符合返回 `errorNo=100`。
- 请求体为 JSON，上限 1 MiB；响应使用统一外壳。
- 状态流转：`pending → approved → enabled → disabled → enabled`；`reject` 可从任意状态执行并清空授权；manifest 版本或哈希变化后回到 `pending`。

| `/api/plugin/manage/approve` | POST | `{pluginId,hooks[],capabilities[]}` | `{pluginId,status:"approved",grantedHooks[],grantedCapabilities[]}` | 405 / 100 |
| `/api/plugin/manage/enable` | POST | `{pluginId}` | `{pluginId,status:"enabled"}` | 405 / 100 / 500 |
| `/api/plugin/manage/disable` | POST | `{pluginId}` | `{pluginId,status:"disabled"}` | 405 / 100 |
| `/api/plugin/manage/reject` | POST | `{pluginId}` | `{pluginId,status:"rejected"}` | 405 / 100 |

`plugins` 元素字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | manifest 的 `id`，等于插件目录名 |
| `name` | string | manifest 的显示名 |
| `type` | string | 固定 `wasm` |
| `version` | string | manifest 版本 |

## 4. 重定向模式（`httpsEnabled != 2` 的 HTTP 服务）

`server/config/config.go:35` 定义：`httpsEnabled` 取 `0`（默认，启用 HTTPS）、`1`（启用）、`2`（不启用）。当取值不是 `2` 时，HTTP 端口**不是完整路由**，只注册 3 条：

| # | 路径 | 处理 | 行为 | 证据 |
| --- | --- | --- | --- | --- |
| R1 | `/.well-known/` | `controllers.AcmeChallenge` | 直出挑战文件，避免 301 导致 ACME 验证失败 | `http_server.go:70`、`:71` |
| R2 | `/api/ping` | `controllers.Ping` | 直出 `pong`，供就绪探针使用 | `http_server.go:72` |
| R3 | `/` | `controllers.Interceptor` | `301` 跳转 `https://{webDomain}{原路径}` | `http_server.go:73`、`server/internal/api/http_redirect.go` |

该模式下 HTTP 服务**不挂** `session.LoadAndSave`（`http_server.go:74`-`:79`），因此不存在 `Token`/session 鉴权路径；对比 `httpsEnabled == 2` 时 HTTP 挂载完整 `router()` 且套 session 中间件（`http_server.go:82`、`:87`）。R1、R2、R3 **不计入第 2 节的 34 条**。

## 6. 主要不一致与风险（仅记录现状，不修改代码）

| # | 现象 | 证据 |
| --- | --- | --- |
| 1 | `/api/email/move` 的 `GroupId` 未传时默认 `0`，`0` 不在 `GroupCodeToName` 中，会走 `MoveMailToGroup(ids, 0)`，把这些邮件强制移到收件箱（`group_id=0`），可能误改发件箱/草稿箱邮件的归属 | `server/internal/api/email_move_handler.go`、`server/internal/app/group_service.go` |
